# Windows 短路径造成记忆更正断链的修复

适用场景：Windows 项目脚本或 MEMORY_DIR 经过 8.3 短路径访问；Linux 项目通过目录符号链接访问时也需要统一路径身份。
症状：更正操作能写出新 Markdown，旧条目也被标记 outdated，但读取 supersedes 后得到额外的 ../ 相对路径，无法对应原记忆键。GitHub Windows runner 的临时用户目录有短路径别名，因而发现本机常规路径测试未暴露的问题。
复现步骤：把脚本复制到临时项目，Windows 使用 GetShortPathNameW 获得脚本短路径并导入，先 add fact，再 add correction --supersedes 旧相对路径，比较 documents 中的 supersedes 与旧条目路径。Linux 使用指向临时项目的目录符号链接可测试相同路径身份要求。
原因：项目根的 abspath 保留短路径或链接别名，reference 的 resolve 则返回真实路径；用不同路径身份计算 relpath 后，结果不再是相同的记忆键。
处理：在导入时统一解析脚本目录、项目根及 MEMORY_DIR 的真实绝对路径；保留 memory 目录内的访问边界。发布工具版本升级为 2.1.1，并补充短路径及目录链接回归场景。本机 9 项离线测试通过。
升级边界：本次只修改当前项目脚本，用户目录 .shared-memory-kit 中的安装副本没有同步。doctor 提示脚本不同或使用全局副本升级其他项目时，应先核对版本并合并修改，避免把修复版覆盖成旧版。
