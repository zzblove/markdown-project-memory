# 共享记忆检索优化与多 agent 兼容约束

背景：用户要求优化 Markdown 项目共享记忆，降低上下文与云端 API 开销，同时保持多个 agent 在同一项目目录共同检索、补充和更正长期知识。
结论：保留 Python 标准库、Markdown 事实源、SQLite 可重建缓存和现有云端嵌入/重排接口；新增摘要与来源/范围元数据、关键词和向量的排名融合、有界 API 响应缓存、命中原文定位和总输出预算。
共享约束：所有 agent 使用同一 memory/；去重检查与发布置于同一进程间写锁；内容变化使检索派生缓存失效，语义索引过期时检索当前 Markdown；更正保留旧正文与关系，不以作者分隔公共知识。
准确性约束：关键词、余弦、重排分分别处理；重排分制明确配置；摘要只做筛选，数字、路径、限制条件以原文为准；不同范围的事实不得合并。
验证策略：隔离真实 key 和网络，在临时目录验证并发写入、更正路径、模型缓存隔离、内容变化、中文/精确名称检索、输出预算和索引失败降级。
被否方案：本次不引入本地大模型、额外向量数据库或每次写入都调用模型的摘要流程；不自动保存全部聊天。
