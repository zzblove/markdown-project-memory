# Markdown 方案 Git 发布边界

背景：用户要求将当前 Markdown 项目共享记忆方案提交到 GitHub。
决策：发布 scripts/mem.py、AGENTS.md、Markdown 项目记忆、中文使用说明及离线测试；SQLite 检索缓存、写锁、API key、独立 SQLite MCP 服务目录和压缩包留在本地，不进入 Git。
理由：Markdown 是可审查与版本管理的事实源，缓存可以在各机器重建；独立服务是另一套部署方案，混入会增加依赖并扩大发布范围。
验证：使用临时目录进行离线回归，覆盖初始化保留原项目约定、并发追加、更正历史、过期索引与外部嵌入失败降级、失败建索引保留旧缓存和原文查看边界。真实项目数据和 API key 不参与这些测试。
被否方案：不直接上传现有压缩包，也不提交本机检索数据库；不自动同步聊天全文。
